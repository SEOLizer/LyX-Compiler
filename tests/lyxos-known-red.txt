# tests/lyxos-known-red.txt — LyxOS-Units, die NICHT uebersetzen, und warum.
#
# Gelesen von: Makefile-Ziel `test-lyxos-units`.
#
# Diese Tests bleiben im Lauf. Sie werden uebersetzt, ihr Fehlschlag ist
# erwartet und bricht das Ziel nicht ab — aber sobald einer wieder UEBERSETZT,
# wird das Ziel rot, damit der Eintrag verschwindet statt zu veralten. Wer
# einen Test aus dem Ziel nimmt, macht ihn unsichtbar; das ist der Unterschied
# zwischen "bekannt rot" und "weggeraeumt".
#
# ── Warum sie scheitern (#1939) ────────────────────────────────────────────
#
# Sie rufen Builtins, deren lyxos-Weg auf Syscall-Nummern der ENTWURFS-ABI
# zeigt: 0x0300 Geraete, 0x0400 IPC, 0x0500 Zeit, 0x0600 Netz, 0x0700
# Capabilities, 0x0800 KI, 0x0900 Lyra, 0x0A00 Debug, 0x0B00 Task, 0x0C00
# IOFS. Diese Kategorien stehen in der ABI-Spezifikation, sind im Kernel aber
# nie gebaut worden (#1734 nennt 106 solcher Phantasienummern).
#
# NACHGEMESSEN am 2026-09-03 mit lyxc 1.1.18A: die Tabelle in
# `lyxosNummerBelegt()` (src/backend/lyxos/emit_lyxos.lyx) ist mit dem Kernel
# deckungsgleich — `tools/sync_syscalls.py` aus `kernel/ring3.lyx` erzeugt 228
# belegte Nummern, und es gibt in BEIDE Richtungen keine Abweichung. Der
# Waechter ist also korrekt und aktuell; es ist keine Nummer nachzuschlagen.
# Was fehlt, ist der Kernel-Teil dahinter.
#
# Der Fehlschlag ist ausdruecklich das gewuenschte Verhalten: eine erfundene
# Nummer stuerzt NICHT ab, der Bootloader liefert fuer Unbekanntes still 0 und
# meldet Erfolg. Diese Pruefung ist die einzige Stelle, die es bemerkt.
#
# NACHGEMESSEN am 2026-10-20 mit lyxc 1.2.16E gegen lyx-os 564aa74 (2026-09-05,
# tools/lyxos_syscall_abgleich.sh: "Stand im Repo ist aktuell"): der Kernel hat
# seit dem ersten Abgleich je Kategorie die ERSTE Nummer bekommen (0x020C,
# 0x0500, 0x0A00, 0x0B06); die Tests scheitern jetzt an der jeweils naechsten.
# Spalte unten: der erste Fehlschlag je Test (#2011).
#
# Wer einen Eintrag entfernen will, hat entweder den Kernel-Syscall bekommen
# oder den Test auf vorhandene Builtins umgeschrieben. Beides ist ein Gewinn,
# beides braucht die Zeile hier weg.

# ── Builtin zeigt in eine nie gebaute ABI-Kategorie ─────────────────────────

# ERLEDIGT am 2026-11-07 (#2011, WP-B): lx10_ipc_test uebersetzt. Der Kernel
# hat 0x0400-0x040C bekommen (kernel/ipc.lyx): Mutex und Semaphor auf eigener
# Tabelle mit LOCK XCHG, nachrichtenorientierte Kanaele (keine VFS-Pipe,
# die schreibt bei vollem Puffer eine Teilmenge), Benachrichtigungsschlangen
# mit Nutzlast, Futex auf die vorhandenen 316-318 abgebildet. Blockierende
# Aufrufe warten nur im Scheduler-Pfad.

# ERLEDIGT am 2026-11-08 (#2011, WP-C): lx11_time_test uebersetzt. Der Kernel
# hat 0x0501-0x0504 bekommen (kernel/timesys.lyx), und 0x0500 wurde dabei
# korrigiert: clock_get ignorierte die Uhrenkennung und lieferte fuer JEDE
# Uhr die monotone Zeit -- CLOCK_REAL meldete also die Laufzeit statt der
# Tageszeit. Timer feuern ohne Haken im Timer-Interrupt (dort ist weder
# Allozieren noch ein Syscall erlaubt): timer_wait rechnet die faelligen
# Ablaeufe aus und schlaeft sonst ueber den Scheduler.
lx14_ai_test            # Builtin-ID 109 → 2048 (0x0800, KI)

# ERLEDIGT am 2026-11-08 (#2011, WP-F): lx08_net_test uebersetzt. Der Kernel
# hat 0x0600-0x0609 bekommen (kernel/sock08.lyx) -- und dafuer musste erst
# die PASSIVE TCP-Seite entstehen: dieser Stapel kannte nur TcpConnect, also
# SYN schicken und auf SYN+ACK warten. Lauschen und Annehmen stehen jetzt in
# net.lyx. Vom Wirt aus nachgewiesen: eine HTTP-Anfrage an die
# QEMU-Weiterleitung wurde angenommen und beantwortet.

# ERLEDIGT am 2026-11-08 (#2011, WP-E): lx12_caps_test und lx07_device_test
# uebersetzen. Der Kernel hat 0x0700-0x0708 bekommen (kernel/caps12.lyx) --
# mit Durchsetzung, nicht nur Buchhaltung: pledge speist die vorhandene
# Capability-Pruefung, unveil wird vor open/unlink/rename/mkdir in BEIDEN
# Dispatchern geprueft, Capability-Deskriptoren in den Lese-/Schreib-/Such-/
# Statuspfaden. Dazu fuer LX-07: sys_pipe3 (351, eigene Nummer fuer unsere
# dreiargumentige Aufrufform), sys_poll (768, nicht blockierend) und
# sys_ioctl (769, nur Fenstergroesse).

# ERLEDIGT am 2026-11-08 (#2011, WP-D): lx13_task_test uebersetzt. Der Kernel
# hat 0x0B00-0x0B09 bekommen (kernel/task13.lyx) -- und damit zum ersten Mal
# echte Ring-3-Threads: ein Task ist ein zweiter Ausfuehrungsstrang IM SELBEN
# Adressraum (eigener Stapel, geteilter Heap). Ende ueber ein Trampolin, das
# sys_task_finish (350) ausloest; das Ergebnis wird dem Wartenden direkt in
# den gesicherten Rahmen zugestellt, weil ein geweckter Thread seinen Syscall
# nicht wiederholt.
lx15_embed_test         # Builtin-ID 119 → 2058 (0x080A, Embeddings)
# lx16_graph_test bleibt rot, aber aus einem ANDEREN Grund als bisher notiert.
# Nachgemessen am 2026-11-08 (#2011, WP-G2): vier der sechs Aufrufe sind im
# Kernel da und nutzen bereits die Entwurfsnummern (Wissensgraph 2063-2066,
# kernel/graph.lyx). Zwei nicht, und sie sind der Grund:
#
#   0x080D sys_sem_annotate(addr, size, embed_fd)
#   0x080E sys_sem_query(query_vec, dim, k, results, max)
#
# Das ist semantisches Paging ueber EMBEDDINGS -- eine Aehnlichkeitssuche
# ueber Vektoren. Dieselbe Maschine, die lx15 braucht und die nach Absprache
# bewusst nicht gebaut wird: es gibt keine Inferenz im Kernel. Einen
# Vektorvergleich vorzutaeuschen (etwa exakte Gleichheit) waere genau der
# stille Erfolg, dessentwegen dieses Issue ueberhaupt aufgefallen ist.
#
# Zweiter, unabhaengiger Befund aus derselben Messung: der Syscall-Block des
# Kernels traegt A0..A3, also VIER Argumente. sys_sem_query und
# sys_graph_query sind fuenfargumentig; bei query ist das fuenfte `max`, die
# PUFFERGRENZE. Sie laesst sich nicht uebergeben, und sie zu raten waere ein
# Pufferueberlauf. sys_graph_edge_add ist deshalb auf die ABI-Gestalt
# umgestellt (das fuenfte Argument ist dort nur meta_len und wird am
# meta-Zeiger abgewiesen), sys_graph_query NICHT -- siehe lyx-os
# kernel/ring3.lyx bei nr == 2064/2066.
lx16_graph_test         # 0x080D/0x080E brauchen Embeddings (wie lx15) + 5-Argument-Grenze
lx17_lyra_test          # Builtin-ID 128 → 2304 (0x0900, Lyra)

# ERLEDIGT am 2026-11-08 (#2011, WP-G3), am 2026-11-09 vom #2441-Abgleich
# bestaetigt: lx18_iofs_test uebersetzt. Der Kernel hat 0x0C00-0x0C04 bekommen
# (kernel/iofs18.lyx) -- hier die ENTWURFSNUMMERN, anders als bei LX-09: 3072
# kollidiert mit nichts. Der "mount_fd" der ABI ist der Platz aus iofs_vol
# (0..3), kein Deskriptor in der FD-Tabelle -- ein Datentraeger ist kein
# geoeffnetes Objekt. compact laesst Mull-und-Fege laufen und schreibt einen
# Pruefpunkt; page_info liest die Kopffelder einer Seite samt
# Pruefsummenbefund; sandbox_enter bindet die KENNUNG an genau einen
# Datentraeger und wird in compact und page_info auch ABGEFRAGT -- Umziehen
# ist nicht erlaubt, sonst waere die Einschraenkung keine.
#
# Der Eintrag muss weg, sonst meldet make test-lyxos-units "UNERWARTET
# GRUEN" -- ein bekannt roter Test, der gruen wird, macht das Ziel rot, damit
# genau das auffaellt.

# ERLEDIGT am 2026-11-07 (#2011, WP-A): lx22_debug_test uebersetzt. Der Kernel
# hat 0x0A01-0x0A05 bekommen -- Ereignisring (kernel/debugtel.lyx), Zyklen und
# Wanduhr als Leistungszaehler (die fuenf PMU-Zaehler melden ehrlich -1, weil
# IA32_PERFEVTSEL nicht programmiert wird), Ruecksprungkette aus dem
# gesicherten rbp/rip des Aufrufers, und Daten-Haltepunkte ueber DR0-DR3 mit
# eigenem #DB-Einsprung (vorher lag Vektor 1 auf der Panikseite).

# ── Kernel hat den Aufruf ueberhaupt nicht ─────────────────────────────────
#
# ERLEDIGT am 2026-11-07 (#2011): sys_gettid (257) und sys_getrandom (258,
# Quelle RDRAND) gibt es seit lyx-os 6187de3; das Backend emittiert sie jetzt
# statt abzulehnen. lx29/lx32/lx33 uebersetzen und sind hier raus.
#
# ERLEDIGT am 2026-11-08 (#2011, WP-G4): lx09_process_test uebersetzt. Der
# Kernel hat die fuenf fehlenden Aufrufe bekommen (kernel/proc09.lyx,
# kernel/task13.lyx), Nummern 352-356 aus dem FREIEN Bereich -- die
# Entwurfsnummern 0x0000-0x000D sind sys_read, sys_close und Nachbarn.
# Dieselbe Entscheidung wie schon bei sys_spawn (91) und sys_getpid (136):
# Gestalt aus der ABI, Nummer aus dem freien Bereich.
#
#   352 sys_thread_spawn(entry, stack, size, arg) -- nimmt den Stapel des
#       AUFRUFERS; LX-13-Tasks teilen sich ihren selbst zu, und den
#       uebergebenen stillschweigend zu ignorieren waere eine Luege.
#   353 sys_thread_exit(code)
#   354 sys_wait(pid, status, timeout_ns) -- timeout 0 sieht nach und
#       antwortet; mit Frist meldet er einen Fehler statt still 0, denn eine
#       0 waere von "Kind laeuft noch" nicht zu unterscheiden (ein geweckter
#       Thread wiederholt seinen Syscall nicht).
#   355 sys_priority(pid, prio) -- ABI-Skala -20..+10, im Kernel auf 0-255
#       umgerechnet. 314/315 bleiben daneben und rechnen bewusst NICHT um:
#       dort ist der Wertebereich die Schnittstelle.
#   356 sys_signal_mask(mask, how) -- es gibt weiterhin KEINE Handler und
#       keine Zustellung, aber eine Maske, die sys_kill (319) tatsaechlich
#       befragt: ein blockiertes Signal beendet den Thread nicht. sig=0
#       bleibt immer erlaubt, sonst waere ein Prozess unsichtbar statt nur
#       unverwundbar.
