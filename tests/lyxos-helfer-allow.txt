# Helferstellen in emit_lyxos.lyx, deren Syscall-Nummer NICHT im Ist-Stand
# steht (work/lyxos/syscall-ist.txt). Erfasst von
# tests/lyxos_syscall_ist_test.sh, Befund aus #2469.
#
# Diese Aufrufe sind NICHT still: emitVfsSyscall prueft die Nummer selbst
# gegen lyxosNummerBelegt() (#1734) und scheitert beim Uebersetzen mit
# genannter Ursache. Die Liste haelt fest, WELCHE Builtins dadurch auf
# --target=lyxos unbenutzbar sind, und WARUM -- fuer "Name da, Emitter da,
# Nummer erfunden" gab es bisher keine Liste. builtin-backend-allow.txt
# (#2458) fuehrt Backend-Luecken, builtin-drift-allow.txt (#1717) Namensdrift.
#
# Format: <Nummer>\t<Builtin>\t<Begruendung>
# Der Test wird rot, wenn eine Stelle dazukommt UND wenn eine verschwindet,
# ohne dass die Zeile hier gestrichen wird.
#
# Stand der Kernel-Seite: lyx-os/doku/syscalls_ist.md, 307 Eintraege.
# Geprueft wurde fuer jede Nummer, ob der Kernel eine Entsprechung hat.

# --- keine Entsprechung im Kernel -----------------------------------------
520	rmdir	Entwurfs-ABI 0x0208. Der Kernel hat sys_mkdir (139) und sys_unlink (97), aber kein Verzeichnis-Entfernen. Auf den Linux-Zielen laeuft rmdir seit #2450 ueber unlinkat/AT_REMOVEDIR; lyxos hat dafuer keine Nummer.
531	sys_symlink	Entwurfs-ABI 0x0213. Im Kernel gibt es keine symbolischen Verknuepfungen -- weder Anlegen noch Auflösen.
532	sys_readlink	Entwurfs-ABI 0x0214. Gegenstueck zu sys_symlink, dieselbe Lage.
533	sys_content_id	Entwurfs-ABI 0x0215. Inhaltsadressierung; im Kernel nicht vorhanden.
772	sys_port_in	Entwurfs-ABI 0x0304. Der Kernel gibt Ring 3 keinen rohen Portzugriff; Geraete laufen ueber DRV-3 (sys_map_device 230, sys_pci_cfg_read 232).
773	sys_port_out	Entwurfs-ABI 0x0305. Gegenstueck zu sys_port_in, dieselbe Lage.

# --- Entsprechung vorhanden, aber ANDERE Gestalt: bewusst nicht umgebogen --
# Eine Nummer mit abweichender Bedeutung einzusetzen waere ein stiller
# Default: der Aufruf wuerde uebersetzen und etwas anderes tun. Beide
# brauchen eine Entscheidung auf Sprachebene, nicht eine Umnummerierung.
525	sys_truncate	Entwurfs-ABI 0x020D, nimmt (pfad, laenge). Der Kernel hat sys_ftruncate (304), das einen FD nimmt. Ein Pfad ist kein FD -- die Abbildung braucht ein open davor und eine Entscheidung, wer es schliesst.
526	sys_sync	Entwurfs-ABI 0x020E. Naechstliegend ist sys_disk_flush (108), das die Schreibcaches der Datentraeger leert. Das ist aehnlich, aber nicht dasselbe wie ein sync ueber offene Dateien.
