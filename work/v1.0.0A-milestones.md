### WP-A2: Windows PE32+ Finalisierung 🔄

**Stand:** IAT-Grundstruktur in `dynamic_linker.lyx` vorhanden.

**Verbleibend:**

1. **Base Relocation Block** (`.reloc`-Section):
   - `IMAGE_BASE_RELOCATION` Header + `IMAGE_REL_BASED_DIR64`-Einträge für alle absoluten Adressen im `.text`
   - Section-Charakteristik: `INITIALIZED_DATA | MEM_READ | MEM_DISCARDABLE`

2. **IAT vollständig verdrahten:**
   - Alle `extern fn … link "dll"` korrekt in Import-Directory eintragen
   - IAT-Section als beschreibbar markieren (Loader-Write)

3. **ASLR-Kompatibilität:**
   - Alle Code-Referenzen RIP-relativ → keine absoluten Relokationen im Textbereich nötig

**Akzeptanzkriterien:**
- `lyxc --target=win64 hello.lyx -o hello.exe`
- `wine hello.exe` gibt "Hello, World!" aus
- `dumpbin /headers hello.exe` zeigt gültige PE32+-Struktur
- Import-Directory enthält `kernel32.dll` mit `ExitProcess` und `WriteFile`

### WP-A3: Struct-Feld `at(offset)` — Sema-Überlappungsprüfung 🔄

**Stand:** Parser (`FIELD_FLAG_PACKED_OFFSET`) und Codegen (expliziter Offset bei Feldzugriff) sind fertig.

**Verbleibend:**
- [ ] **Sema:** ConstExpr-Prüfung, Überlappungsprüfung, Gesamtgröße = max(Offset + sizeof(Field))

**Akzeptanzkriterien:**

### WP-A4: `@big_endian` — ARM64 REV-Emission 🔄

**Stand:** Parser, Sema (f64-Fehler) und Codegen x86_64 (`BSWAP`/`XCHG`) sind fertig.

**Verbleibend:**
- [ ] **Codegen ARM64:** `REV16` / `REV32` / `REV64` nach Load, vor Store

**Akzeptanzkriterien:**
- Round-trip auf ARM64: `hdr.src_ip := x; var y := hdr.src_ip;` → `y == x`
- `REV32` im ARM64-Binary sichtbar

---

### WP-A5: ARM64 libc init fix ✅

**Implementiert:** 56-Byte `_start`-Stub, der `__libc_start_main(main,argc,argv,NULL,NULL,NULL,sp)` aufruft.

**Umgesetzt:**
1. 56-Byte `_start`-Stub: ADR x0, #56 (main) + LDR x8 GOT-Slot + BLR x8 + fallback exit
2. GOT-Slot bei Stub-Offset 48 (VA `0x401030`), R_AARCH64_GLOB_DAT RELA-Eintrag
3. `__libc_start_main` in `.dynsym` (UNDEF GLOBAL FUNC, Index `nExt+1`)
4. `libc.so.6` automatisch als DT_NEEDED wenn noch nicht in user externs
5. `--no-libc-init`-Flag: überspringt CRT-Init, nutzt 12-Byte BL-Stub
6. Statische Binaries (kein extern fn): unverändert (12-Byte-Stub wie bisher)

## Phase B — Safety-Features

---

### WP-B1: Triple Modular Redundancy (`@redundant`) ✅

**Implementiert:** x86_64 fast-path — 3 Slots (A=&var, B=&var+8, C=&var+16), Majority-Vote + Self-Heal.

**Layout (codegen_x86):**
- Slot A = `[rbp+off-16]` (niedrigste Adresse; `@x` gibt `&A`)
- Slot B = `[rbp+off-8]` = `&A + 8`
- Slot C = `[rbp+off]`   = `&A + 16`

**Majority-Vote-Algorithmus (inline, 64 Bytes x86_64):**
- A==B, A==C: alle gleich, return A
- A==B, C≠A: heal C, return A
- A==C, B≠A: heal B, return A
- A≠B, A≠C (B==C oder alle verschieden): use B, heal A

**Test:** `tests/lyx/safety/test_tmr_redundant.lyx` (6 Testfälle, alle PASS)

**Einschränkung v1.0.0A:** nur skalare Integer; kein Thread-Safety; nur x86_64 (IR-Backends folgen)

---

### WP-B2: Secure Post-Patching (`.meta_safe` Compiler-Pass) ⬜

**Stand:** Laufzeit-API (`MetaSafeVerify`, `MetaSafeGetPageHash`) in `std/meta_safe.lyx` fertig. Compiler-Pass fehlt.

**Verbleibend:**
1. **Compiler-Flag:** `--meta-safe` aktiviert den Pass nach dem Binary-Writer
2. **CRC32 pro 4K-Seite:** Jede 4096-Byte-Seite aus `.text` separat hashen
3. **`.meta_safe`-Section schreiben:**
   - Format: Magic `0x4D455441` (4B) + PageCount (4B) + Array `{pageOffset: uint32, crc32: uint32}`
   - ELF: `SHT_NOTE`, `SHF_ALLOC | SHF_READONLY`

**Akzeptanzkriterien:**
- `lyxc --meta-safe hello.lyx` erzeugt Binary mit `.meta_safe`-Section
- `MetaSafeVerify()` = 0 bei unverändertem Binary
- Nach `dd`-Modifikation einer `.text`-Seite → `MetaSafeVerify()` = -1

**Stand:** `SqrtF64`, `SinF64`, `CosF64`, `TanF64`, `ExpF64`, `LogF64`, `Log10F64`, `PowF64`, `TruncF64`, `FloorF64`, `CeilF64`, `RoundF64`, `AbsF64`, `MinF64`, `MaxF64`, `GCD`, `LCM`, `IsPrime`, `NextPrime` sind fertig.

- [ ] `Atan2F64(y, x): f64` — Quadranten-korrekter Arkustangens

**Akzeptanzkriterien:**
- `AsinF64(1.0)` ≈ π/2 (Abweichung < 1e-12)
