## P0 — Muss für V1.1.0

### S1 — WP-A4: `@big_endian` ARM64 REV-Emission — ⛔ BLOCKIERT, → V1.2
**Befund (2026-06-22, Investigator-Audit):** Annahme „nur REV emittieren" ist falsch.
`@big_endian` lebt AUSSCHLIESSLICH im AST-direkten `codegen_x86.lyx` (Prod-Codegen für
linux/macos/win x86_64). Der **IR-Pfad** (`ir.lyx`/`ir_lower.lyx` → `emit_arm64.lyx`,
auch IR-x86) hat **null** big_endian-Support. Schlimmer: `ir_lower.lyx lowerField`
(2336) ist für **Instanz-Feldzugriff ein Stub** (emittiert kein IRO_LOAD_FIELD, „dest
stays 0"). Empirisch: `--target=arm64` auf einem Struct-Feld-Programm erzeugt kein
lauffähiges ARM64-ELF (qemu: „Invalid ELF image").

→ WP-A4 setzt einen funktionierenden **ARM64-IR-Feldzugriff** voraus. Das ist ein
eigenes, größeres Stück („ARM64-IR-Backend-Reife"), kein P0-Quick-Item. **Verschoben
nach V1.2** als Teil einer dedizierten ARM64-Backend-Aufgabe. Backend-Parität bleibt
auf x86_64 (3 OS) vollständig; ARM64 ist als Target vorhanden, aber für OOP/Structs
unreif.

**Plan wenn angegangen (3 Schritte):** (1) IR-Feld-Opcodes big_endian+Breite in
`immInt` Bits 8+ kodieren; (2) `ir_lower` aus `@big_endian`-AST (parser.lyx:2107
FIELD_FLAG_BIG_ENDIAN) extrahieren + Feld-Lowering vervollständigen; (3) REV/REV16/REV32
in `emit_arm64` nach Load / vor Store. Vorher Instanz-Feld-Lowering im IR-Pfad fixen.

### S2 — Kleine Korrektheits-Bugs
- **`--std-path` off-by-one** (`src/lyxc.lyx:793` `arg + 10` → `arg + 11`): liefert sonst `=PATH`. Test: `--std-path=/x` setzt `/x` (nicht `=/x`).
- **Makefile `VERSION`** (`Makefile:16` `0.9.10D` → `1.0.0A`): `.deb`-Paketname/-Version stale.
**Abnahme:** beide gefixt; je 1 Regressionstest/Check.

### S3 — FFI-Sandbox vollständig fail-closed
V1.0 schloss den Fail-Open im **link-Branch** (#815, FFI_CLASS_UNKNOWN + ffiTrusted). Reste:
- **no-link-Branch** (`_checkFuncDecl`, c3==-1): unbekannte no-link-Externs in User-Code laufen noch durch (nur Blacklist). Auf dieselbe UNKNOWN-Fail-Closed-Logik bringen.
- **PROCESS-Klasse** (fork/kill/clone…): `_checkExternFn` behandelt FORBIDDEN/OS/UNKNOWN, aber **PROCESS fällt durch → ohne @cap erlaubt**. Sollte wie OS @capabilities/@cap erfordern.
**Abnahme:** `extern fn fork()` (no-link, user) ohne @cap → Fehler; std-Builtins/trusted unverändert; make test grün.

## P1 — Sollte in V1.1.0

### S4 — Security #28: Kernel-Mode-Guard-Erweiterung
`std.net.epoll` + gesamtes `std.net.*` in die `@kernel_mode`-Forbidden-Allowlist (POSIX-abhängige Imports in `--target=lyxos-kernel` blocken). Verifizieren gegen Code (Doku evtl. stale). Test ergänzen.

### S5 — Security #29: Lizenz-Secret-Architektur
XOR-Obfuskation → asymmetrisch (das Lizenz-Secret liegt aktuell verschleiert im Binary). Ed25519-Infra existiert bereits (WP-29). Test.

### S6 — `.deb`-Packaging
`make package` zu einem installierbaren `.deb @ 1.0.0A` bringen (sync-units + precompile-units + install-bin). Abnahme: `dpkg -i` installiert, `lyxc --version` = 1.0.0A, std-Units auffindbar.
