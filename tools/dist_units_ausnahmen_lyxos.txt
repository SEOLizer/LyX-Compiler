# Units, die fuer --target=lyxos NICHT vorkompilierbar sind. Jede Zeile nennt
# ihre Ursache mit Issue-Nummer -- ein Eintrag ohne Grund waere der stille
# Default, den tests/dist_units_ziel_2472_test.sh verhindert.
#
# Gemessen 2026-11-15 mit lyxc 1.2.40E, jede der 503 Dateien in std/** und
# data/** EINZELN uebersetzt und das Erzeugnis geprueft: 494 uebersetzen,
# genau diese neun nicht.
#
# Bis #2513 waren es 90 -- eine Liste dieser Laenge waere ein Feigenblatt
# gewesen, deshalb stand lyxos bis heute auf `host` und lieferte die
# x86-64-Units aus. Genau das war der Befund in #2532: die ausgelieferten
# .lyu trugen keinen IR-Abschnitt und waren fuer dieses Ziel unbrauchbar.
#
# Die neun zerfallen in zwei Gruppen, und der Unterschied ist wichtig:
#
#   DAUERHAFT (3) -- plattformeigen per Entwurf. Diese Zeilen bleiben.
#   OFFEN (6)     -- rufen sys_sendto/sys_recvfrom noch in der Linux-Form mit
#                    6 Argumenten; LyxOS nimmt 4 (ABI 10.9/10.10). Das ist
#                    dieselbe Umsetzung, die std/net/socket.lyx schon traegt
#                    (dort zielweise verzweigt, dst_uva = {ip, port}), nur an
#                    sechs weiteren Stellen nicht nachgezogen -- Restarbeit
#                    aus #2513, als #2541 geführt. Wer sie erledigt, nimmt
#                    die Zeile hier weg; bleibt sie stehen, obwohl die Unit
#                    uebersetzt, meldet der Waechter das.
#
# Fuer die fuenf Bluetooth-Units ist in #2541 zuerst die Adressform am Kernel
# zu klaeren: socket.lyx schreibt {ip, port}, ein L2CAP- oder RFCOMM-Ziel ist
# aber keine IP. Faellt die Antwort "LyxOS erreicht Bluetooth nicht", werden
# aus diesen fuenf dauerhafte Ausnahmen -- dann wandern sie in die obere
# Gruppe, mit genau dieser Begruendung.

# ── dauerhaft ────────────────────────────────────────────────────────────────
std/security_ext_x86.lyx                  # sys_arch_prctl gibt es auf LyxOS nicht; der Aufruf setzt die Segmentbasis und ist x86-eigen. Bewusst getrennte Unit -- #2512
std/net/internal/syscalls_linux.lyx       # roher Linux-Syscall-Wrapper; traegt die Linux-ABI im Namen und soll fuer LyxOS gar nicht uebersetzen. Der portable Weg ist std.net.socket -- entschieden in #2532
std/net/internal/syscalls_android.lyx     # dasselbe fuer Android (Bionic-ABI); auf LyxOS ohne Bedeutung -- entschieden in #2532

# ── offen, #2541 ─────────────────────────────────────────────────────────────
std/net/syscalls.lyx                      # sys_recvfrom in Linux-Form (6 statt 4 Argumente); nicht Linux-eigen, importiert seit #2511 std.net.wait -- gehoert gezogen wie socket.lyx. #2541
std/hardware/bluetooth.lyx                # sys_sendto in Linux-Form; Adressform fuer L2CAP/RFCOMM am Kernel offen. #2541
std/hardware/bluetooth_l2cap.lyx          # sys_sendto in Linux-Form; Adressform offen. #2541
std/hardware/bluetooth_rfcomm.lyx         # sys_sendto in Linux-Form; Adressform offen. #2541
std/hardware/bluetooth_gattc.lyx          # sys_sendto in Linux-Form; Adressform offen. #2541
std/hardware/bluetooth_ai.lyx             # scheitert ueber import std.hardware.bluetooth_gattc, nicht an eigenem Code -- faellt mit #2541 von selbst weg
